# 仿真演进与验收策略评估

## 问题陈述

当前规划明确"本轮直接接入 Gazebo 或真实硬件"不在范围内（PRD §5），并强调"FakeLidar、未来 Gazebo bridge 和真实驱动进入同一标准 ROS 边界"（PRD §2.8）。但缺少以下内容：

1. **仿真分级定义**：什么是 Level 0/1/2/3？各级的目的和充分性标准？
2. **演进路径**：C1-C8 各子任务在哪个仿真级别验收？何时升级到下一级？
3. **Gazebo 集成的必要性和范围**：是可选的辅助工具还是核心验收依赖？
4. **实物集成准备**：从仿真到实物需要哪些额外决策和验收门？

## 候选方案

### 方案 A：明确四级仿真演进策略（推荐）

**定义四个仿真级别**：

```
Level 0: 纯软件（Pure Software）
  - FakeLidar + FakeOdom + 确定性逻辑链路适配器
  - 固定 seed，完全可重复
  - 无物理仿真、传感器噪声或动力学约束
  - 用途：算法逻辑验证、确定性回归、CI/CD、conformance suite
  - 验收标准：oracle 对比通过、replay 字节级等价、故障注入覆盖率

Level 1: 软件仿真（Software-in-the-Loop, SIL）
  - 可选 Gazebo bridge + 简化动力学（或其他物理引擎）
  - 传感器噪声模型、基础碰撞检测
  - 用途：噪声鲁棒性验证、3D 可视化、场景构建辅助
  - 验收标准：算法在噪声下不退化为 Unavailable、可视化辅助调试
  - 非强制：Level 0 已验证的逻辑不需要在 Level 1 重复验证

Level 2: 半物理仿真（Hardware-in-the-Loop, HIL）
  - 真实传感器数据 → 仿真环境中的虚拟飞行器
  - 或：仿真传感器 → 真实飞控硬件
  - 用途：硬件接口验证、延迟测试、实时性验证
  - 验收标准：真实设备与仿真系统无协议冲突、实时性满足预算
  - 属于后续扩展，不在 C1-C8 范围内

Level 3: 实物测试（Field Test）
  - 全真实硬件 + 受控环境（隧道、室内）
  - 用途：最终验收、环境不确定性、长时运行稳定性
  - 验收标准：实际隧道探测任务完成、安全边界有效
  - 属于后续扩展，不在 C1-C8 范围内
```

**C1-C8 演进路径**：

- **C1-C7**：全部在 **Level 0** 验收，Level 1 可选用于可视化和调试辅助
- **C8 总验收**：**Level 0 必须通过**，Level 1 可选演示
- **C9a/C9b**：仍在 Level 0，但增加故障注入覆盖率（进程 crash、主机故障）
- **后续独立子任务**：Level 2/3 集成（不在当前父任务范围内）

**Gazebo 集成范围**：

- **可选工具**，不是核心验收依赖
- 如果使用，必须满足：
  - 输出标准 `LaserScan`/`PointCloud2`/`Odometry`
  - 通过与 FakeLidar/FakeOdom 相同的 conformance suite
  - 不引入仅 Gazebo 可用的特殊接口
- 主要用途：场景可视化、噪声注入、开发者调试
- 不用于：物理精度验证、动力学约束测试（留给 Level 2/3）

**实物集成准备（独立扩展）**：

- 硬件适配指南（HAL 层设计）
- 实物测试安全预案（紧急停止、安全区域）
- Level 2 验收标准（真实传感器与算法集成）
- Level 3 验收标准（实际隧道探测任务）

---

### 方案 B：只定义 Level 0，其他留待扩展

**定义 Level 0（纯软件）**：

- 唯一的强制验收级别
- FakeLidar + FakeOdom + 确定性链路适配器
- 完全可重复、oracle 对比、conformance suite

**Gazebo 和实物集成**：

- 完全留作后续独立扩展
- 不在父任务和 C1-C8 中讨论
- 不提供演进路径指引

**优点**：规划范围最小，避免过早设计

**缺点**：

- 缺少从仿真到实物的清晰路径
- Gazebo 的定位不清（是否应该在 C1-C8 中集成？）
- 实物集成时可能需要大幅返工

---

### 方案 C：Level 0 + Level 1 强制，Level 2/3 可选

**Level 0 + Level 1 都是核心验收依赖**：

- C1-C8 必须在 Level 0 和 Level 1 都通过
- Gazebo 成为必须集成的组件

**优点**：早期验证噪声鲁棒性

**缺点**：

- 引入 Gazebo 依赖，增加 CI/CD 复杂度
- Gazebo 世界构建成本高
- 传感器参数映射的准确性无法保证（Level 1 无法验证真实设备一致性）
- 与 PRD §5 "本轮直接接入 Gazebo"矛盾

---

## Evidence

**支持方案 A 的证据**：

1. **PRD §5 明确排除 Gazebo**："本轮直接接入 Gazebo 或真实硬件"不在范围内
2. **D-010 确定性链路适配器**：已定义 Level 0 的核心机制
3. **多处 fixture 要求**：FakeLidar、FakeOdom、确定性故障注入都是 Level 0 组件
4. **验收标准重点**：replay、oracle 对比、conformance suite 都是确定性验证方法
5. **隧道探测特性**：需要在线规划和障碍避让，Level 0 已足够验证算法正确性

**反对方案 C 的证据**：

- PRD §5 已明确 Gazebo 不在本轮范围内
- 现有验收标准未要求噪声鲁棒性测试（只要求确定性和逻辑正确性）

**方案 B 的风险**：

- 缺少仿真演进路径可能导致后续实物集成时架构不足

---

## Accepted Direction

**接受方案 A**：定义四级仿真演进策略，C1-C8 在 Level 0 验收，Level 1 可选。

**决策要点**：

1. **Level 0 是核心验收级别**：FakeLidar/FakeOdom/确定性链路适配器，完全可重复，oracle 对比和 conformance suite 通过。
2. **Level 1 是可选辅助工具**：Gazebo 可用于可视化和调试，但不是验收依赖；如使用必须通过与 Level 0 相同的 conformance suite。
3. **Level 2/3 留作独立扩展**：半物理和实物测试不在 C1-C8 范围内。
4. **实物集成准备**：明确需要硬件适配指南、安全预案、Level 2/3 验收标准，但不在父任务中实施。

**写入 design.md 的决策点**：

`Accepted(D-031)`：采用分级仿真验收策略。Level 0（纯软件）：FakeLidar、FakeOdom、确定性链路适配器，完全可重复，用于算法逻辑验证和 CI/CD；C1-C8 在 Level 0 验收。Level 1（软件仿真）：可选 Gazebo 集成用于传感器噪声注入和可视化，如使用必须通过与 Level 0 相同的 conformance suite；Level 1 不是核心验收依赖。Level 2（半物理）和 Level 3（实物）：真实传感器/飞控与算法集成，验证硬件接口、实时性和实际隧道探测任务；留作后续独立扩展，不在 C1-C8 范围内。每级仿真有明确的验收门和回退策略；Level 0 必须证明算法正确性和确定性。
