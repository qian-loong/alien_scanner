# C1/C2 感知性能与内存重测

## 目标

在真实链路、真实几何下，覆盖全部重构后节点，回答两个核心问题：

1. **有没有内存泄漏**——分两个维度，本轮全部自建证据链：
   - 经典泄漏（malloc 丢失 / 越界 / UAF）：sanitizer 真实路径覆盖
   - 可达内存无界增长：拼接回放长跑的周期基线斜率
2. **CPU 占用多少、瓶颈在哪个节点**

## 背景

上一轮基线（已归档 `07-27-c2-performance-memory-baseline`）用合成 fixture
喂单个产品节点做隔离测量，有三处范围限制：

- **覆盖 2/7 节点**：只测了 C1 与 C2，其余节点从未测过
- **输入非真实**：合成隧道横截面替代真实洞穴几何，且只验证过消息契约等价、
  未验证资源行为等价；**sanitizer 结论只覆盖合成输入激发的代码路径**
- **CPU 是隔离下界**：测量时只有 3 个轻量进程，真实链路 6 节点争用同一批核

本任务改用**真实链路 bag 录制回放**，并且**全新采集**：不复用任何既有测量
数据（含 2026-08-02 之前的所有 run），可复用的仅有脚本、夹具与构建基础设施。
旧数据只作脚本调试参考，不进报告。

方法论依据：`docs/performance-memory-testing-cookbook.md`。

## 范围

### 被测对象

**仅产品节点**：`perception_input_node`（C1）、`perception_local_map_node`（C2）。

夹具节点（`cave_publisher`、`fake_odom`、`cave_laser_scan`、
`pose_gated_laser_scan_relay`）只在集成轮被**顺带采样**——目的是测量卫生
（证明它们没有在窗口内污染测量、量化其对产品节点的 CPU 争用），
**不做任何专项测试**。不测重构前节点（`swarm_controller`、`scan_accumulator`、
`fake_lidar`）。

### 核心机制：录制回放 + 拼接长跑

| 测谁 | 回放什么（从 bag-all 按话题选取） |
| --- | --- |
| C1 | `LaserScan`(原始) + `Odometry` + `/tf`、`/tf_static`（S1 切点） |
| C2 | `LidarObservation` + `PoseEstimate` + `HealthState` + `/tf`、`/tf_static`（S3 切点） |

泄漏长跑用**重打戳拼接 bag**（机制与冒烟证据见 design.md）：裸
`ros2 bag play --loop` 已实测不可行（时间戳高水位门全量拒收）。

## 验收标准

- **AC1**：3 轮集成直采完成（每轮约 50 s，覆盖完整 20 s 运动段），全部 7 个
  节点 + 录制器同时采样 CPU/RSS/PSS/USS，每轮保留 raw 与 `sha256sum.txt`。
- **AC2**：每节点 CPU 排序与占比（产品/仿真区分）、RSS/PSS/USS 峰值与均值、
  系统总内存 = **PSS 求和**（不得用 RSS 相加）、每单位工作的内存成本；
  **饱和度显式呈现**（10 Hz 输入下的丢帧率/积压结论）；端到端延迟分布作为
  **记录型指标**给出（标注"仅供量级参考，不作验收判据"）。
- **AC3**：C1/C2 回放隔离基线完成，回放等价门通过（observation 数、最终
  revision/体素数与直连一致），C2 含阶段延迟分解。
- **AC4**：泄漏双维度证据链闭合：
  - sanitizer 真实路径覆盖：C1/C2 各完成 ASan+LSan 单圈、2 份拼接 bag 单圈
    （覆盖 epoch 重置路径）、Memcheck 一遍；**阳性对照**被正确抓住；
  - 长跑：C1/C2 各 ≥30 min 拼接回放，周期等价门通过，给出周期基线斜率结论 +
    **灵敏度下限** + 覆盖边界。
- **AC5**：报告遵守 cookbook §7 表述纪律——绝对值带不确定度、容量结论标注
  本机观测值、clean 报告只对实际执行过的路径负责；记录与真机已知差异。

## 非目标

- 不做 oracle 精确真值迁移，以计数等价门替代。
- 不测夹具与重构前节点的专项指标。
- 不设计任何依赖 <10% CPU 差异的判据（环境分辨率不支持，cookbook §6）。
- 不做 Callgrind 函数级归因（移出关键路径；需要时另立 finding）。
- 不做 S2（排序版）确定性回归基线回放（素材保留在 bag-all 中，无当前消费者）。
- 不做性能优化实现。发现热点或缺陷另立 finding。

## 约束与执行纪律

- 测量环境无硬件 PMU，CPU 时间带约 ±30% 争用污染——这是**环境属性而非指标
  制约**：本机只做排序级 CPU 结论；换目标硬件后可用同一套脚本做精确预算验收。
- **新问题处置纪律**：新发现的问题先问"是否阻塞两个核心问题的回答"——
  不阻塞 → 记 finding 继续走；阻塞 → 限时 2 小时修复，超时上报而非继续挖。
- 测量脚本的测试**冻结现状**，不再扩张。
- 容器曾多次卡死。每个有效 run 完成后**立即归档摘要到宿主机**，不等整批跑完。
- 有效性门分两级（详见 design.md）：**阻塞门**仅 bag 可读、回放/周期等价、
  阳性对照三类；其余（PID 身份、角色退出码、residual sweep、provenance）降级
  为**标注**——记录并评估影响，不作废 run、不当场重跑。

## 已知风险

| 风险 | 说明 |
| --- | --- |
| C1 拼接回放未冒烟 | C2 已验证；C1 可能有类似拒收路径，先做 5 min 冒烟，有问题修拼接工具、不改产品 |
| bag play 时序保真度 | 对内存/CPU 影响小，对延迟分位数有影响，报告标注 |
| ASan 下 C1/C2 能否跟上 10 Hz | 跟不上则 `--rate 0.5`，放慢不损失路径覆盖，用计数等价核对兜底 |
